# FarmSolver

Расчётный планировщик Stardew Valley 1.6.15: 69 видов семян и саженцев всех сезонов, календарь роста, графики прибыли, переработка, кулинарные рецепты и подключаемые наборы модов.

## Локальный запуск

Нужен Node.js 22 или новее; в GitHub Actions используется Node.js 24. Из корня проекта:

```sh
npm run dev
```

Открыть http://127.0.0.1:4173/. Устанавливать зависимости не нужно. `npm test` запускает проверки расчётов и загрузки сайта из подпапки GitHub Pages. Если npm не установлен, те же команды доступны через `node --run dev`, `node --run dev:pages` и `node --run test`.

Для предпросмотра именно адреса проекта:

```sh
npm run dev:pages
```

Открыть http://127.0.0.1:4173/FarmSolver/. При переименовании репозитория можно передать новый путь: `node demo/server.mjs --base /new-name/`.

## Публикация на GitHub Pages

1. Загрузить изменения в репозиторий `veryDeepWell/FarmSolver`.
2. В **Settings → Pages → Build and deployment → Source** выбрать **GitHub Actions**.
3. В **Actions → GitHub Pages** запустить **Run workflow** для `main` либо отправить новый коммит в `main`.
4. После успешной публикации адрес появится в результате задания **Publish GitHub Pages**. Для текущего репозитория стандартный адрес — https://veryDeepWell.github.io/FarmSolver/.

Workflow находится в `.github/workflows/pages.yml`. Изменения в `main` автоматически проверяются и публикуются; pull request запускает только проверки. В настройках окружения `github-pages` при необходимости нужно разрешить публикацию из `main`. Отдельные токены и секреты не нужны: workflow использует стандартный `GITHUB_TOKEN`.

На хостинг отправляется только `demo/dist`: HTML, CSS, модули JavaScript, игровые PNG и JSON-примеры. Сервер, справочные загрузки, тесты и исходники инструментов не публикуются. Сборки и серверной части нет: расчёты, графики и импорт наборов работают в браузере. Все локальные пути относительные, поэтому сайт подходит и для подпапки репозитория, и для собственного домена. Файл `.nojekyll` отмечает каталог как готовый статический сайт.

Если у репозитория другая основная ветка, заменить `main` в workflow. Фиксировать `/FarmSolver/` в приложении или менять ссылки при переименовании репозитория не требуется.

Сценарии и наборы хранятся в localStorage конкретного браузера и адреса сайта. При переходе со старого демо-домена они автоматически не переносятся; JSON-наборы нужно подключить заново.

## Расчётная модель

Первичные данные отделены от расчётов. Прибыль и производные цены вычисляются; исключения с фиксированными игровыми ценами заданы правилами рецептов. Наборы модов подключаются JSON-файлами во вкладке «Моды»; поддерживаются фильтры сезона, повторного сбора, категории и набора. Это формат FarmSolver, а не прямой импорт файлов игровых модов.

Подробности: [архитектура](demo/ARCHITECTURE.md), [пример набора](demo/dist/packs/example.json), [схема](demo/dist/packs/schema.json). Все допущения доступны в интерфейсе во вкладке «Формулы».

Сравниваются монопосевы с бюджетом на весь период. Смешанные оптимальные планы, реинвестирование и расписание загрузки оборудования пока не моделируются. Пунктир графиков показывает потенциальную стоимость переработки, а не деньги в день урожая.
