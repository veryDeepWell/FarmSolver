# FarmSolver

## Размещение на GitHub Pages

Приложение — готовый статический каталог `demo/dist`, без обязательного сервера и стадии сборки. `.github/workflows/pages.yml` проверяет расчёты и загрузку относительных ресурсов, затем публикует только этот каталог через GitHub Pages Actions. PR не публикуется. Старый манифест Sites удалён; для приложения не нужны API или параметры прежнего хостинга.

Все импорты, изображения и скачиваемые JSON используют относительные URL. Для project Pages не нужен жёстко заданный base URL. `npm run dev:pages` из корня запускает тот же каталог под `/FarmSolver/`; `demo/check-pages.mjs` дополнительно проверяет другой путь, MIME-типы модулей и загрузку зависимостей. `demo/server.mjs` нужен исключительно для локального предпросмотра.

## Границы слоёв

- `dist/data/vanilla.mjs`: первичные игровые факты. 69 записей: 45 культур, чайный куст, 6 смесей, 8 плодовых деревьев, 7 лесных деревьев и 2 вида травы. Производные цены и готовая прибыль здесь не хранятся.
- `dist/data/cooking.mjs`: 68 кулинарных рецептов, использующих выращиваемые ингредиенты либо их промежуточные продукты. Фиксированные цены выхода — самостоятельные игровые правила; стоимость ингредиентов вычисляется.
- `dist/registry.mjs`: проверка и объединение наборов. Ключи `pack-id:crop-id` изолируют культуры модов. Реестр не исполняет код из данных.
- `dist/model.mjs`: чистые функции календаря, бюджета, денежного потока и рецептов. `calculate` принимает культуру, сценарий и реестр, не обращается к DOM или хранилищу. `products` использует линейные формулы либо явно фиксированные рецепты. `processingProjection` — потенциальная стоимость переработки, а не производственный календарь.
- `dist/charts.mjs`: SVG-график и календарь, полученные из результатов модели. График имеет текстовое описание и таблицу ежедневных значений.
- `dist/app.mjs`: фильтры, карточки, сохранение, CSV и импорт/отключение модов. Пользовательский текст экранируется при выводе.

## Расширение модами

Формат и пример: `dist/packs/schema.json`, `dist/packs/example.json`. Импорт через вкладку «Моды». Это нейтральный формат FarmSolver, а не прямой загрузчик SMAPI/Content Patcher/Json Assets. Для их поддержки следует добавить адаптеры, преобразующие поля в этот формат, сохранив идентификаторы модов.

Каждая культура задаёт `seed`, `base`, `grow`, `regrow`, `yield`, `type`, `group`, `seasons`, ограничения `year`, `special`, `stock`. Необязательные `recipes` заменяют универсальные рецепты. Формула `linear` задаёт `multiplier × base + offset`, формула `fixed` содержит фиксированную игровую цену. Число входов и выходов задаётся полями `input` и `output`. Иконка может быть локальным PNG или PNG base64; без неё используются инициалы.

Набор проверяется целиком перед подключением. Дубликаты id наборов и культур отклоняются. Подключённые наборы и правки исходных фактов хранятся под `farmsolver-v2` в localStorage текущего браузера; база игры включена в поставку. Сброс сценария сохраняет наборы и правки; правки культуры сбрасываются отдельно в её карточке.

## Модели роста

Обычная культура: первый рост, затем повторный сбор или повторный посев. Поддерживаемые сезоны проверяются каждый день; при несовместимом переходе рост прекращается. Горизонт — до конца одного, двух или четырёх сезонов. Плодовые деревья растут во все сезоны, плодоносят только в свои; в теплице и на острове плодоносят круглый год. Чай собирается только 22–28 числа. Лесные деревья и трава имеют случайный рост, поэтому не получают ложной даты созревания; взрослые деревья рассчитываются отдельным переключателем. Грибное и мшистое дерево имеют явные упрощённые сценарии в карточках.

Смеси считаются по взвешенным исходам одной начальной партии. Их средняя стоимость не подменяет базовую цену какого-либо продукта. Повторные посевы и повторный сбор случайно выпавших культур пока не моделируются.

## Следующие точки расширения

Для реального производственного расписания нужен отдельный планировщик мощностей: парк машин, время загрузки, очереди, точные игровые минуты и выдержка. Его завершённые события будут входить в денежный поток вместо линии потенциала. Для оптимизации смешанного участка и реинвестирования нужен отдельный решатель; текущее ранжирование сравнивает монопосевы с заранее зарезервированным бюджетом.

## Данные и проверка

Первичные факты и игровые спрайты 1.6.15 получены из `juliaramosguedes/stardew-data`; готовые поля `_calc` отбрасываются. Цены покупки и особые правила сверены со Stardew Valley Wiki. `fetch-reference.mjs` загружает справочные JSON в игнорируемую папку `reference`; `build-catalog.mjs` формирует нормализованные данные и загружает нужные PNG. Спрайты и игровые материалы принадлежат ConcernedApe. Никаких пакетов из источника не устанавливается и код источника не запускается.

`npm test` проверяет сезонные переходы, крайние дни, повторный сбор, бюджет, смеси, многолетники, формулы и исключения, округление, изоляцию модов, совпадение графиков с итогами и наличие PNG.
